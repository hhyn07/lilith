## 垃圾桶 `/trash`
- **刪除筆記改成移到垃圾桶**（軟刪除）：Note 模型開啟 `paranoid`，使用資料表**原本就有**的 `deletedAt` 欄位（HedgeDoc 早期的 migration 留下的，後來上游關掉了），所以**不需要新的 migration**。開啟前確認沒有任何筆記的 `deletedAt` 有值。
- 開啟後所有 HedgeDoc 的查詢都自動略過垃圾桶裡的筆記（首頁推薦、公開個人頁、書本、編輯器…）；編輯器自己的「刪除這篇筆記」也會進垃圾桶。
- 頁面：筆記名稱、刪除日期、預計永久刪除日期；「還原」「永久刪除」「清空垃圾桶」（後兩者會再確認）。
- **還原**：回到「紀錄」最上面；資料夾與收藏都還在（移到垃圾桶時不刪這些）。
- **永久刪除**：一併刪掉修訂版本、作者紀錄、資料夾／收藏紀錄。
- **30 天**後永久刪除：在擁有者打開垃圾桶時處理（沒有排程）。TRASH-4 會在超過 37 天還沒處理時提醒。
- 只有擁有者看得到自己的垃圾桶；操作都要登入、JSON、頻率限制；用筆記 UUID 加擁有者條件查，碰不到別人的筆記。
- 資料匯出（`/me/export`）也包含垃圾桶裡的筆記。
- 刪除前先停伺服器備份：`備份/db.hedgedoc.sqlite.bak-20261016-before-trash`。

## 我的活動 `/activity`
- 依日期（今天／昨天／日期）列出：**你建立了**、**你編輯了**、**你把筆記移到垃圾桶**、**某人編輯了你的筆記**，最多 100 筆。
- 從筆記資料表推算，沒有另外記錄：每篇筆記只顯示最近一次編輯（同一篇之前的編輯不會出現）。這點寫在頁面說明。
- 在垃圾桶裡的筆記標示「在垃圾桶」，連結指向垃圾桶。

## 測試
- 臨時帳號：刪除筆記→提示「已移到垃圾桶」、從紀錄消失、資料庫 `deletedAt` 有值；訪客開原網址被導回首頁、不會產生新筆記；垃圾桶頁顯示；還原→回到紀錄；收藏後刪除再還原，收藏還在；永久刪除後 Notes／Revisions／Authors／LilithNoteMetas 都清掉；把一篇的 `deletedAt` 改成 31 天前（只改測試帳號的資料）→ 打開垃圾桶時被清掉；清空垃圾桶；我的活動顯示「建立了」「移到垃圾桶」「在垃圾桶」。
- 直接查資料表的檢查（06、07、17、19、21）加上 `deletedAt IS NULL`，排除垃圾桶裡的筆記。
