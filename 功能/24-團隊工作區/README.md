## 權限規則（`lib/teams.js`）
| 角色 | 團隊筆記（含私人） | 改權限、刪除 | 管理成員、邀請連結、團隊垃圾桶 | 刪除團隊 |
|---|---|---|---|---|
| 擁有者（建立者，一個） | 讀、寫 | ✅ | ✅ | ✅ |
| 管理者 | 讀、寫 | ✅ | ✅ | |
| 成員 | 讀、寫 | | | |
| 筆記建立者 | 保有原本所有權利 | ✅ | | |

- 「私人」的團隊筆記 = 只有團隊成員看得到。新增團隊筆記預設就是私人。
- 接在 HedgeDoc 四個判斷點：`note/util.js` 的閱讀權限（發表頁、下載、書本、API）、`realtime.js` 的閱讀、編輯（ifMayEdit）、改權限與刪除。
- 編輯器前端也有自己的判斷（`havePermission`），所以伺服器在 `refresh` 資料裡帶 `teamRole`，前端據此讓成員打字、讓擁有者／管理者使用權限選單。
- 這些判斷是同步的，所以 `lib/teams.js` 在記憶體保存「誰在哪個團隊」「哪篇筆記屬於哪個團隊」，啟動時從資料表載入，每次變更都先寫資料表再更新記憶體。

## 刪除時
- **刪除團隊**：成員移出；團隊筆記**不刪**，回到各自建立者的「我的空間」。
- **刪除帳號**：離開所有團隊；擁有的團隊交給第一位管理者（沒有就第一位成員），沒人了就刪除團隊。
- **永久刪除筆記**：同時移出團隊。帳號刪除時資料庫直接刪掉的筆記，其團隊紀錄在下次啟動時清掉。

## 測試（兩個臨時帳號 A、B）
- A 建立團隊、新增團隊筆記、把個人筆記移入團隊、用 Email 加入 B（成員）；重複加入、不存在的 Email 有提示。
- B（成員）：看得到兩篇**私人**團隊筆記（編輯頁、發表頁、下載都 200）、可以改標題；不能刪除、不能加人、不能產生邀請連結（403）；看不到成員 Email。訪客打開被導走。
- **即時編輯**：B 在編輯器輸入文字 → 存進資料庫、最後編輯者是 B；B 的權限選單是鎖住的（成員）。
- A 把 B 升為管理者：B 可以刪除（進團隊垃圾桶）、看到團隊垃圾桶、還原；不能移除擁有者、不能改擁有者角色。
- B 離開團隊 → 立刻 403；用邀請連結重新加入（成員）→ 200。
- 用顯示名稱加入、`%` 不會變成萬用字元。
- 刪除團隊：成員、團隊筆記紀錄清掉，筆記還在、B 立刻 403。
- 設定頁、團隊垃圾桶畫面在瀏覽器確認。
- 帳號刪除的 hook：擁有者刪除後管理者成為擁有者，最後一人刪除後團隊消失。
- 測完刪除所有測試帳號、筆記、團隊與 session。
