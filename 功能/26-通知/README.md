## 需求來源
- prompt 106：「參考 hackMD」＋HackMD 通知面板截圖。面板有鈴鐺、一般通知／重要通知分頁、只顯示未讀、全部標示為已讀，項目依日期分組，顯示「X 和其他 N 個人 變更了〈筆記〉」與變更內容。

## 規則（`lib/notify.js`）
| 分頁 | 什麼時候產生 | 誰會收到 |
|---|---|---|
| 一般通知（`change`） | HedgeDoc 存版本時（編輯中每 5 分鐘一次；改標題、標籤也會叫醒存版本） | 筆記建立者、筆記所屬團隊的成員、收藏這篇的人；**不含做變更的人**；**只有讀得到這篇的人** |
| 重要通知（`team`） | 被加入團隊、角色被改、被移出、團隊被刪除；有人用邀請連結加入（通知擁有者／管理者） | 當事人（自己離開不通知任何人） |

- 做變更的人 = 筆記最後編輯者＋上一個版本之後**新寫入文字**的人（authorship 的建立時間）。不能用 authorship 的更新時間：別人刪掉你的字時，你的那筆也會更新（E1）。
- 同一篇筆記、同一天、還沒讀的一般通知會**合併成一則**：人名累加、變更內容接在前面（最多 1600 字）。
- 變更內容是版本 patch 的增（綠）／刪（紅、刪除線）＋前後最多 40 字的上下文，`↵` 表示換行，不同段之間用 `⋯`。
- 打開面板時**重新檢查閱讀權限**：離開團隊或筆記改成私人後，舊通知不再顯示內容與連結，標「（已無權限）」；筆記刪除則標「（已刪除）」。
- 90 天前的通知在打開面板時清掉；帳號刪除時一併刪除。

## 測試（兩個臨時帳號 A、B，A 的團隊筆記）
- A 把 B 加入團隊、升為管理者 → B 收到兩則重要通知。
- A 改筆記 → B 收到一般通知，內容正確；A 自己沒有。A 再改 → B 仍是一則，內容合併。
- B 改標題 → A（建立者）收到一般通知，B 沒有新的。
- 瀏覽器（B）：鈴鐺 3、面板兩個分頁、變更內容、全部標示為已讀後鈴鐺變 1、只顯示未讀顯示空白提示；編輯器頁與垃圾桶頁都有鈴鐺。
- API：標示未讀、刪除、A 刪 B 的通知 404、訪客 401、表單格式 415。
- B 離開團隊 → B 的舊通知沒有連結與內容、標「已無權限」；自己離開不通知 A。
- 測完刪除測試帳號、團隊、筆記、session 與通知。

## 已知限制
- 通知要等 HedgeDoc 存版本（最多約 5 分鐘）才出現，不是即時。
- 鈴鐺每 60 秒查一次，不是推播。
- HackMD 截圖裡的「社群」「公告」分頁沒有做：個人自用的站沒有社群動態與官方公告的來源。
